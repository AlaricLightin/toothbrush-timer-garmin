# Development workflow

1. **Scope the change.** Read the [repository rules](../AGENTS.md), [product requirements](product-requirements.md), and [technical design](technical-design.md). Inspect Git status, relevant code, and tests. Consult [UI design](design/ui-design.md) for visual changes. Resolve specification conflicts and obtain required approvals before editing affected code or documents. Treat possible extensions as uncommitted until requested. Reflect approved contract changes in the specification before implementation.
2. **Plan active work.** Use a short working plan for small tasks. For larger tasks with dependencies or multiple delivery steps, keep scope, ordered steps, verification checkpoints, and implementation and acceptance status in `doc/implementation-plan.md`. Link to specifications. When asked to continue, compare the plan with code and checks, then take the first incomplete implementation step. Ask for clarification if the next step is ambiguous. If implementation is complete, report outstanding acceptance. Continue independent implementation while simulator or hardware acceptance is pending.
3. **Implement and verify.** Follow the [README commands](../README.md#setup) and [development procedures](development.md). Preserve independent regression coverage. Run the affected [checks](testing.md) and report tooling failures separately. Keep environment workarounds out of application code. Record artifact-specific results and limits in [verification](verification.md).
4. **Review the diff.** Check requirements, correctness, regressions, tests, maintainability, device compatibility, and scope. Fix defects and repeat affected checks and review. After at most two correction iterations, report any remaining defects, attempted fixes, and likely causes.
5. **Close the task.** Update affected documents and active plan status. Follow the handoff rules in AGENTS.md. For planned work, include the completed step, review findings and resolutions, and correction count. Once implementation and applicable acceptance are complete, retain lasting decisions in the relevant specification, procedure, or verification baseline and remove the completed plan.
